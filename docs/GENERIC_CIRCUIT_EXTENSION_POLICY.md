# 通用电路扩展策略

项目不按“一个电路一个运行器”无限扩展。现有 RC、RLC、OPAMP 运行器是验收基准，用来验证生成、原生仿真、拓扑核验和报告链路。

后续新增电路时按以下层次处理：

1. **逻辑网表层**：描述元件、引脚、网络和设计约束。自然语言模型只能提出合同，不能直接写 XML。
2. **组件适配器层**：为新器件提供符号模板、引脚顺序、模型参数、版本映射和可观测输出。常见电阻、电容、二极管、晶体管、运放、逻辑门应复用适配器。
3. **拓扑编译层**：统一生成节点、端口和导线；不为每种放大器或滤波器复制连接代码。
4. **原生验收层**：统一导出 Multisim 网表，检查引脚网络，再运行 OP/AC/TRAN 和理论/约束判据。
5. **优化层**：在同一合同上替换参数、器件或拓扑候选。

只有在出现新器件族、特殊仿真模型、特殊观测量或版本差异时，才新增适配器或验收插件。普通的串并联、滤波、放大、整流和逻辑组合应由通用网表与布局层处理。

当前还需要验证真实器件模型、组合瞬态、电气额定值、复杂反馈以及多板实际执行，不能只将剩余工作归为布局问题。

2026-09-09 已新增统一的 `run_generated_analog_project`，在同一运行器上完成两级和四级 RC＋理想运放的原生 OP/AC 验收。[工作流、真实边界与器件接入经验](COMPOSED_ANALOG_WORKFLOW.md)记录了结果；后续优先扩展模型族与通用分析器，不新增“一个复杂电路一个运行器”。
