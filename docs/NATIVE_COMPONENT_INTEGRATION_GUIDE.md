# 原生元件接入与失败经验

2026-09-09 已新增 [真实 LM324AJ 与瞬态插件验收记录](THESIS_PLUGIN_ACCEPTANCE_20260909.md)。
接入前必须额外核对模型换行往返、关联 CiModel 对象、数字开头的分单元引脚、
端子语义与模板文件顺序，以及全新模板包中的探针三对象。LM324M 替换试验仍失败，
不能把同系列芯片名称当作已验证别名。

接入新的 Multisim 元件不能只验证 XML 能否生成。必须同时验证符号、引脚、连线、
模型、探针和原生输出枚举。RLC 回归暴露了一个典型问题：元件连通性报告正确，
但第二个电压探针没有进入 Multisim 的可用输出列表，仿真因此必须失败关闭。

## 统一接入门槛

每个新元件或新拓扑至少经过以下阶段：

1. **无 COM 解析**：SPICE 行、单位、引脚数、模型参数和默认值严格校验。
2. **生成前检查**：模板存在、元件数量正确、每个引脚映射到声明网络。
3. **布局检查**：每个网络有足够的连接、没有孤立引脚、导线端点落在元件连接器上。
4. **探针绑定检查**：记录探针目标网络、导线段数量和选定挂接点；不能只依赖图像看起来相连。
5. **原生打开回读**：Multisim 打开 `.ms14` 后重新导出连通性和元件清单。
6. **输出枚举**：`ReportNetlist` 后重新调用 `enum_outputs()`；请求的每个电压、电流通道必须存在。
7. **最小分析**：先运行 OP，再运行覆盖目标频段的 AC 或覆盖边沿的 TRAN。
8. **理论对齐**：用独立理论模型逐点比较原生数据，不能只检查“仿真完成”。
9. **版本回归**：每个 Multisim 版本、Python 位数和模板包都单独记录证据。

## 失败处理规则

- 元件缺失、模型丢失、隐藏引脚、输出通道缺失、矩阵不完整或轴不一致，都必须返回
  明确失败原因。
- 不能用源网表仿真结果替代 Multisim 原生结果。
- 不能因为 XML、PNG 或连通性文本生成成功，就宣称电路已验证。
- 每次失败保留输入网表、生成 XML、`.ms14`、连通性报告、可用输出列表和 manifest，
  便于定位是模板、布局、探针还是 COM 回读问题。

## 当前 RLC 经验

RLC 网表、元件、连通性回读和原生 AC 已通过。历史失败点包括输出节点探针未进入
Multisim 可用输出列表，以及二极管模型对象缺少本机模板中的空参数容器；这两类问题
已分别通过独立探针枚举门禁和完整 `CiModel` 结构回归修复。后续接入元件仍应优先复用
这些结构化回读与原生输出检查，不能放宽验收器或改用未验证的数据来源。
