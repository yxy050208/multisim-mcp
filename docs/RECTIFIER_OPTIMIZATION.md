# 原生整流电容优化闭环

`optimize_natural_rectifier` 使用真实 Multisim 实验选择滤波电容，完成候选比较、工况验证、保存后复验及报告导出。它复用已有原生工程副本执行器与 RLC 参数修改接口，不以估算值代替仿真。此功能属于源码开发版，尚未进入已发布的 1.3.0rc1 安装包。

## 一句话使用

向连接本项目 MCP 服务的 Agent 提出：

> 设计12V交流输入、100mA负载的桥式整流电路，纹波不超过0.3V，在满足要求的前提下尽量减小滤波电容，导出工程和优化报告。

对应调用（`experiment`、`optimization` 或 `full` profile）：

```json
{
  "name": "optimize_natural_rectifier",
  "arguments": {
    "text": "设计12V交流输入、100mA负载的桥式整流电路，纹波不超过0.3V，尽量减小滤波电容",
    "output_dir": "D:/experiments/rectifier-opt-001",
    "execute": true
  }
}
```

默认仅预览，不启动 COM、不创建目录；执行需要一个新目录、本地授权 Multisim 14.3 及已提取的元件包。现有安装/模板说明见 [原生整流验收](RECTIFIER_NATIVE_ACCEPTANCE.md)。这是同步的有界实验，运行需要数分钟；宿主应给予足够工具调用超时。验收脚本使用 1800 秒读取超时：

```powershell
python tools/run_rectifier_optimization_acceptance.py --output D:/experiments/rectifier-opt-001
```

该脚本通过真实 MCP stdio 调用，核对返回值与落盘验收一致，递归校验所有层级的 manifest。运行过程的最新实验位置保存在 `checkpoint.json`；当前不承诺取消后自动恢复或断点续跑。

## 搜索与验收规则

1. 生成并验证公式初选基线；固定基线负载电阻，后续不能通过改变标称负载掩盖纹波问题。
2. 比较九个离散电容：470、680、1000、1500、2200、2700、3300、3900、4700μF。每个标称候选均通过 Multisim 的 `SetRLCValue` 修改工程副本，再进行 OP/TRAN。
3. 从标称通过的最小候选开始，验证输入 90%/110%、半载/满载、电容 80%/120% 的八个组合。半载使用两倍电阻，不是恒流负载；工况电流目标按输入比例和负载比例缩放，允许 ±10%。所有组合保持用户要求的纹波上限。
4. 角点平均输出允许范围固定为基线估算平均电压的 80% 至基线输入峰值的 110%，在预览中公开；该范围适用于未稳压电源，不是用户指定的恒定输出电压。
5. 所有运行核对模型、全部引脚、有效 R/C 参数、输入正弦、稳态均值/纹波、电阻负载电流和相邻窗口稳定性。启动电压需在五个输入周期内进入稳态均值的 ±10%（或纹波上限，取较宽者）并保持至仿真结束；检查零起点、完整时域和采样峰值。
6. 一个工况不通过即可排除候选，剩余未执行工况不会标为通过。工作进程错误、缺失原始数据、参数回读失败等属于证据不完整，停止搜索并返回失败，不能据此证明较小电容不可行。
7. 选定候选后，复制该次实验**真正保存的 `.ms14` 文件**，重新打开且不修改参数，复验全部标称指标。核对源文件摘要保持不变，均值和纹波复验差异不超过 2% 或 5mV（取较宽者）。

“最小”仅指上述离散候选集合内，通过全部声明工况的最小标称容量；不是连续范围、全部器件或全部物理工况的全局最优。明确指定固定电容的请求会被拒绝，以免优化器擅自覆盖硬约束。

## 2026-09-13 本机结果

通过中文目录的真实 MCP 调用，执行 **27 次原生运行**（每次 OP + TRAN），而非只生成网表。

| 方案 | 标称纹波 | 最差已测工况纹波 | 结论 |
| --- | ---: | ---: | --- |
| 基线 4700μF / 153.64Ω | 0.159674V | 未执行完整基线角点集 | 标称通过，作为优化前对照 |
| 2700μF | 0.322145V | — | 标称不通过 |
| 3300μF | 0.268379V | 0.319446V | 标称最小候选；输入+10%、满载、容量−20%时失败 |
| **3900μF** | **0.192589V** | **0.270031V** | **标称及八个组合全部通过，最终选定** |

最终工程回读电容为 **0.0039F**（原生图面显示 **3.9mF = 3900μF**），电阻仍为 **153.64Ω**。无改参重开后的平均输出 **15.072382V**，负载电流 **98.101941mA**，采样电压建立时间约 **4.54ms**。相对基线电容减少 **17.02%**，代价是标称纹波有所增加，但仍满足要求。更大的基线电容没有因此被宣称完成全部容差验证。

本次目录含 1026 个文件条目，包括所有失败候选、各次原生工程和原始数据；主报告提供候选汇总、工况表和优化前后波形。原始工程及 NI 派生模型文件仅保存在本机，不进入公开代码仓库。

## 导出结构

- `report.html`、`comparison.csv`、`comparison.svg`：优化前后及工况对照。
- `baseline/native/circuit.ms14`：原始方案。
- `candidate-*/`：标称及已执行组合的实际工程、图纸、CSV、参数回读和报告。
- `delivery/native/circuit.ms14`、`delivery/native/schematic.png`：选定工程重新打开复验后的交付件。
- `delivery/report.html`：最终复验数据和波形。
- `acceptance.json`、`manifest.json`：完整结果及文件摘要。

失败时保留实验和报告，`winner=null`、`delivery_status=not-ready`。报告导出失败也不能返回整体成功。

## 原生参数缓存的接入经验

本机 Multisim 14.3 的 `SetRLCValue` 会更新 `CiaParamList/parameters` 中的有效表达式，但 `doubles` 字段可能仍保留修改前的缓存。例如从 4700μF 改成 3300μF 后，字符串是 `3.3m`，数值缓存仍是 `0.0047`。

已通过保存后重新打开、不再写值的实验确认，`RLCValue` 和实际仿真使用更新后的有效参数。因此新的复验路径同时要求：

- 每次原生分析前的 `RLCValue` 与设计一致；
- 保存文件中的有效参数字符串与设计一致；
- 两项分析的原生参数读回一致；
- 最终选定文件在无改参重开后再次通过验收。

缓存差异单独留档，不修改 NI 文件缓存来伪造一致性。缺少原生读回证据时仍采用严格缓存检查；有效字符串或原生读值错误都会失败。

尚未验证源阻抗、浪涌电流、二极管热耗散、电容 ESR/额定纹波电流、电阻/二极管容差、频率偏差、PCB 或实物安全。当前完成的是有限参数与工况的**原生仿真优化闭环**。

最新源码还会在每次整流验收中生成 `electrical_stress_review`：以原生输出和负载计算实际负载功率，并给出电阻功率、电容耐压和桥式 PIV 的保守选型下限。该状态固定为 `requires-rated-part-selection`，直到接入带额定值的器件目录和浪涌/热模型；它不会把未建模的额定值伪装成仿真通过。
