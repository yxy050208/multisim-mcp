# 开源研发与产品资产边界

自 2026-10-10 起，本仓库以有可复现实验证据的前沿工程能力为研发重点，继续推进复杂
电路生成、元件映射、原生连接与参数验证、仿真、报告、协议兼容及基本多板联调。
电路图的基本引脚连接正确性、错误修复和如实报告验证结果仍属于开源核心。

基本多板联调以明确的板归属、连接器引脚和测试夹具合同为输入，包含逐板生成工程、
保存重开和连接回读、逐板仿真、跨板接口一致性检查及汇总报告。这些能力可以在开源版
继续扩展和修复；具体可用范围由目标版本、元件映射及实机回归证据决定。

商业版重点提供便于安装和使用的产品体验，包括商业安装包、配置引导、完整操作流程、
升级和支持。现有开源安装、CLI 和 MCP 接入保持兼容；新增多板联调优化、跨板参数/
拓扑联合搜索、整体目标优化及高级元件布局/排线优化仍在独立商业产品中维护。
已经进入公开 Git 历史或发行包的相关实现保留原有 MIT 授权和贡献者归属；本规则限定
后续开发与资产导入，不能撤回已经公开的许可。

技术领先的定位须以公开基准、原生实验凭据和可复现流程支撑；尚无当前同类产品的系统
比较时，不将“最先进”作为已经证明的结论。

免费商品包可以引用公开核心，但“免费”不等于所有附带素材都已开源。商品介绍、
安装包、私有模型、客户案例和评测数据须单独确认来源，不能因存放在同一工作区而
进入 GitHub、公开 PyPI、npm 或 MCP Registry。

商业源码和商品资产应放在独立私有仓库及仓库外的产品目录。仅用同一公开仓库的不同
分支隔离并不可靠：分支仍可推送到公开远端，合并或打包也可能带入私有内容。
商业分支中的通用修复若需回流，先提取独立补丁并核对文件来源和许可。

发布审计拒绝路径段为 `commercial`、`commercial_assets`、`private`、`proprietary`、
`paid` 或 `agensi-products` 的候选文件，以及 ZIP/7z/RAR/tar 等商品或归档容器。
`.gitignore` 只是减少误暂存；审计也检查已经跟踪或强制暂存的文件，wheel/sdist
检查则核对实际包成员。CI、PyPI、npm 和 MCP Registry 工作流均在发布步骤前执行审计。

这些检查不能识别所有改名的私有代码或证明资产权属，文件来源审查仍是必要步骤。
本仓库不会保存商业商品、客户资料或平台账号内容。
