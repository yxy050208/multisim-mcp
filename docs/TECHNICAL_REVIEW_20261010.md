# 开源研发与技术栈审查（2026-10-10）

## 结论

保留 Python、MCP、独立 32 位 COM worker、Multisim/ngspice 后端与实验凭据体系。
当前具备有明确验收边界的工程自动化核心，主要不足集中在需求到电路的通用编译、
原生工程格式适配和已验证元件/版本覆盖。下一阶段重点是把专用流程汇成可组合的
设计与验收链路，减少每增加一个应用场景就新增一套流程的成本。

开源继续前沿电路研发和基本多板联调；商业版重点做安装、配置、操作体验、升级与支持。
后续专有多板优化和高级布局/排线优化仍独立维护。具体边界以
[`OPEN_SOURCE_SCOPE.md`](OPEN_SOURCE_SCOPE.md) 和根目录 `AGENTS.md` 为准。

## 开发历程的实际价值

1. 从基本仿真控制发展到原理图生成、原生重开、拓扑/引脚/模型/参数回读、实验和报告。
   历史 XSPICE 模型丢失、数字负载丢失和探针交叉问题表明，纯网表仿真与原生工程正确性
   必须分别验收；这些修复和门禁构成可复用的适配知识。
2. 建立有界实验、参数扫描、可逆补丁、任务恢复、失败诊断、版本化 manifest 和哈希清单。
   它们让模型提案能够进入可审计流程，而非仅生成一段电路描述。
3. 仓库记录包含五个数字回归案例、十三个混合信号案例，以及双板数字矩阵的两个案例、
   六次 DC/TRAN/AC 分析。对应原生证据主要来自 Multisim 14.3 和已明确验收的元件族。
4. 基本多板已覆盖显式板归属、连接器/夹具合同、HDR1X4 逐针物化、逐板原生分析、
   跨板接口与完整参考比较。未声明边界条件、无版本映射或缺少证据时保持未验证。

记录见 [`DIGITAL_REGRESSION_MATRIX.md`](DIGITAL_REGRESSION_MATRIX.md)、
[`HYBRID_REGRESSION_MATRIX.md`](HYBRID_REGRESSION_MATRIX.md) 与
[`MULTIBOARD_DIGITAL_REGRESSION.md`](MULTIBOARD_DIGITAL_REGRESSION.md)。
上述案例不能证明任意复杂电路、任意厂商 ADC/DAC、物理 PCB 或生产认证已经完成。

## 技术栈判断

| 层 | 判断 | 需要处理的问题 |
| --- | --- | --- |
| Python 3.10+ 与领域服务 | 适合工程编排、协议、数据处理和快速实验，继续保留 | `schematic_builder.py` 4658 行、`server.py` 4175 行、`cli.py` 3924 行，职责较密集；按实际扩展点逐步拆分 |
| MCP、CLI、loopback API | 适合接入不同宿主；已有 profile 减少工具上下文 | 工具数量不是自主设计能力；宿主行为和内部模型 Agent 的能力需分别说明 |
| 模型提供器与有界工具循环 | 已有 OpenAI-compatible、DeepSeek、Ollama 等配置与工具调用抽象 | 内部 `model_engineering.py` 主要复述并核对 RC 需求，`ReadOnlyEdaTools` 只读；未形成通用复杂电路自主设计 Agent |
| 32 位 COM worker | 合理隔离旧 EDA 依赖，前端可用 64 位 Python | Windows/Multisim 运行时仍必须可用；64 位前端不改变 32 位 COM 的约束 |
| XML 模板与 ewd/ewe 编解码 | 目前能交付可编辑原生工程，是最需谨慎维护的适配层 | 依赖本机模板、引脚/模型语义及 `electronics-workbench-decoder@0.2.0`；格式与版本变化必须独立回归 |
| ngspice | 有价值的开放后端与可在 CI 复现的实验环境 | 方言、模型与求解器差异必须留证；其成功不能替代 Multisim 保存重开后的原生实验 |
| 结构化设计、审批与报告 | 已有 `CircuitDesign`、来源网表、模型引用和实验合同，可继续复用 | 结构化组件与来源网表需持续检查一致性，所有入口应复用相同验收和可交付状态 |

NI 的 [Automation API 文档](https://www.ni.com/docs/en-US/bundle/multisim/page/topics/api-reference.html)
确认官方自动化接口存在，本项目已使用该类 COM 接口。当前适配器仍明确记录
`native_component_placement=false`、`native_wire_drawing=false`，成图路径为
`template-xml-ms14-codec`。不能把当前生成过程描述为全面调用官方元件放置/绘线 API。
项目价值集中在需求约束、原生交付验证、实验和凭据闭环。

保持 `EdaBackend` 扩展边界，可跟踪
[KiCad 官方 IPC API](https://dev-docs.kicad.org/en/apis-and-binding/ipc-api/for-addon-developers/)。
官方文档区分 KiCad 9/10 与 11 的图纸、导出和无界面能力，并提示默认文档可能包含开发版
功能；近期不以未经目标版本验收的新后端替换已验证的 Multisim 核心。

## 当前最关键的能力缺口

- **统一编译能力不足。** `COMPILER_SUPPORT_MATRIX` 只有 `signal-passive` 一项。
  运放、晶体管、整流、组合模拟等已有专用入口，但尚未全部贯通统一的方案审批编译链。
- **复杂自然语言与复杂网表不是同一能力。** 宿主 Agent 可提交受支持网表，内部模型入口
  仍有明确 RC 范围；模型接入成功不代表任意需求都能变成可验收电路。
- **多板边界仍有限。** 当前双板数字案例用显式电压夹具复现输入并比较完整参考。
  这不是自动求解任意板间双向负载、阻抗、反馈、热或寄生耦合的联合仿真。
- **版本覆盖集中。** 仓库只有 `components-14.3.json`；其他版本不能借用 14.3 结论。
- **能力说明存在漂移。** rc3 发布说明仍保留较早提交/测试数字，模板目录中的数字与系统
  类别仍标为 planned，而矩阵已有部分原生记录。需要区分目录、入口、编译、映射和实验
  各自的成熟度，避免整类声明过宽或已验证案例无法被发现。

不能据目前材料给出可靠的整体完成百分比，也没有同一基准下的竞品对照证明“最先进”。
可合理定位为专注 Multisim 原生交付与实验验证的开源工程自动化核心，并用公开基准验证
其在这一具体方向的差异化能力。

## 下一阶段顺序与验收

| 顺序 | 交付 | 完成判据 |
| --- | --- | --- |
| 1 | 统一能力状态与发布基线 | 以入口、元件族、目标版本和证据定位能力；文档、发现接口与测试一致；本地加固另用新候选版本发布 |
| 2 | 可组合的方案编译链 | 先贯通现有无源/运放调理与已验证接口，将模块端口、供电、模型、单位和网络合同编译为同一 `CircuitDesign`；支持的组合通过，缺失模型/非法连接明确拒绝 |
| 3 | 固定双板传感器采集示范 | 模拟调理板与接口板使用已验收元件/连接器和明确夹具，完成逐板生成、原生回读、DC/AC/TRAN、接口与完整参考比较、图纸和汇总报告 |
| 4 | 保留需求的跨方案回归 | 用未硬编码的需求与指标变体验证解析、单位和编译；记录模型调用、实际值、失败原因、实验预算和可复现率，避免只重复一个成功参数组 |
| 5 | 版本与元件覆盖 | 有相应授权环境后建立其他目标版本独立清单和原生矩阵；每个新增元件族先做模型/引脚/行为验收 |

示范工程可从已验证的信号调理、滤波和逻辑接口组成，不先承诺未映射的真实 ADC 芯片。
行为模型与厂商模型分开标记。采样轴若使用重采样，记录比较依据和边界；不将离散点通过
解释为连续时间、实物或安全认证。

扩展的基本单位应是已验证的元件族、模块端口和实验合同，而非为每一种整电路重复写模板。
组合后仍必须检查新的电气相互作用；元件已验收并不自动证明任意组合正确。
基本多板接口与一致性验证保持开源，专有全局多板优化及高级排线在商业产品中继续隔离。
